# Evaluation Stage 1

## Submission Requirements

- **Kaggle Write‑up** (up to 2 000 words) covering all 5 rubric criteria with 3 required figures: (1) an architecture diagram, (2) a score‑vs‑cost plot, and (3) a dev‑set failure breakdown.
- **GitHub repository link** and **40‑character commit SHA** (`git rev-parse HEAD`).
- Repository root must include:
  - `submission.yaml`
  - `serve.py` / `harness.py`
  - an Apache‑2.0 or MIT license
  - the unpacked `artifacts/` directory (≤ 512 MiB, ≤ 10 000 files, no Git LFS or symlinks).
- If the repo is private during the competition, install the [PLE‑submission GitHub App](https://github.com/apps/ple-submission/installations/new) and make the repo public at competition close.
- **`model_api`** in `submission.yaml` must be set to one of the 8 official `google-cloud/<id>` models for Stage 2 evaluation.
- **Pass both checks** before submission:
  ```bash
  uv run python -m kit check
  uv run python -m kit artifacts
  ```
  The `artifacts/` directory must be generated by `uv run python eval/run.py`.

## Minimum Checks

1. **Write‑up** is present, correctly formatted, and includes the required sections and figures.
2. **Repository layout** meets the specification above.
3. **`submission.yaml`** contains a valid `model_api` field referencing an official Google Cloud model.
4. **Artifacts validation** succeeds (`kit check` and `kit artifacts` both return success).

## Rubric (100 pts total)

| Criterion | Points | What Judges Look For |
|---|---|---|
| **1. Insight & Failure Analysis** | 25 | Teach something non‑obvious about engineering agents. Show real dev‑set failures (misreading a drawing callout, picking the wrong code clause, unit errors, stopping early), controlled ablations ("We added X, and the dev score went from A to B"), and ideas that failed or were surprising. |
| **2. Engineering Reasoning** | 25 | Walk through a concrete dev‑set task and compare your agent's trajectory against a licensed engineer's workflow. Highlight where reasoning held up, where shortcuts were taken, and domain‑specific challenges. |
| **3. Cross‑Model Generalizability** | 15 | Compare ≥ 2 sponsored models from different families. Identify changes that improve all models vs. those that help only one. Provide a table of `model_api`, baseline scores, your scores, deltas, token usage, and cost per task. |
| **4. Efficiency & Scaling** | 20 | Present a score‑vs‑cost plot (Fig 2). Discuss scaling with turns, tokens, or parallel checks, where performance plateaus, and how you stay within the 6‑hour limit. |
| **5. Reproducibility** | 15 | Confirm that `uv run python -m kit check` and `uv run python -m kit artifacts` pass on your SHA. Include notes for judges on how to reproduce the run, any required environment variables, and how to verify artifacts. |

---

**Note:** The competition blocks custom API keys, external model servers, and web search during Stage 2 evaluation. Use the official Google‑provided key for the selected `google-cloud/<id>` model.
